# v0.2 Evaluation & Model Improvement

## Goal

v0.2 turns the v0.1 VOC classifier into a measurable CX Operations system.

The purpose is not to add more AI features. The purpose is to answer:

- How accurate is the classifier?
- Which labels are confused?
- Does it catch high-risk VOC?
- Does human-review routing create too many false positives?
- How much measured API usage does an evaluation run consume?
- Did a prompt/taxonomy change actually improve the same dataset?

## Dataset policy

`evals/gold/voc_gold_seed_v0.2.csv` contains 200 synthetic, pre-labeled seed cases covering all 38 v0.1 subcategories.

Important: these rows are `label_status=provisional`.

They are useful for checking evaluation code, finding obvious taxonomy/prompt weaknesses, and preparing human review. They are **not** a publishable gold benchmark until a person reviews each row and changes approved rows to `label_status=reviewed`.

Never publish provisional metrics as portfolio performance.

## Evaluation metrics

For reviewed rows, the evaluator calculates:

- Major category accuracy
- Major category macro precision / recall / F1
- Subcategory accuracy
- Subcategory macro precision / recall / F1
- High-risk precision / recall
- Human-review precision / recall / F1
- Per-subcategory support / precision / recall / F1
- Major and subcategory confusion matrices

Failed API rows are excluded from quality metrics and counted separately.

## Error analysis

Every mismatch is exported with a suggested error family. The Evaluation Lab also provides a manual `error_type` field: taxonomy ambiguity, prompt issue, customer-message ambiguity, incorrect gold label, model reasoning issue, priority policy, or human-review policy.

## Provenance and cost

Every live run preserves model, prompt version, taxonomy version, dataset label version, input/cached/output tokens, and estimated cost only when dated prices are explicitly configured.

## Workflow

1. Review the 200 seed labels.
2. Change accepted rows to `label_status=reviewed`.
3. Run the baseline classifier.
4. Inspect confusion matrices and error analysis.
5. Define one focused prompt/taxonomy hypothesis.
6. Run the candidate against the exact same reviewed rows.
7. Compare summaries with `python -m evals.compare_runs`.
8. Keep the change only if quality improves without unacceptable guardrail regression.

## Commands

```bash
python -m evals.run_gold_eval
python -m evals.run_gold_eval --include-provisional
python -m evals.compare_runs evals/results/<baseline>_summary.json evals/results/<candidate>_summary.json
```

Trend Detection and Root Cause Analysis remain out of scope until this evaluation loop is credible.
